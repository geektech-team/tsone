# TSone CLI 固定样式静态产物设计

**日期：** 2026-10-10
**状态：** 待审阅

`tsone build` 自动将固定样式集生成可缓存的 CSS 文件，应用维持现有写法。
范围包括 `document.styles`、组件 `initStyles()` 中通过 `StyleManager`
注册的固定规则，以及能明确识别的新建 `StyleManager` 的固定初始化。
无法确认固定的规则继续使用运行时样式路径。

组件静态样式仍随管理器实例激活和销毁。后续增删改恢复动态样式，保持规则
顺序和实例之间的层叠关系。首屏保留同步内联样式，直到对应外链加载成功。
优化目标是文档 CSS 跨页面复用、组件 CSS 静态缓存及外链承载。组件首次
初始化仍保留同步样式生成。规则对象保留在 JavaScript 中以支持动态回退，
本次不承诺减少全部样式对象的 bundle 体积或消除首次初始化序列化。

## 现有行为

- `packages/tsone-cli/src/build.ts` 已让 Bun 打包导入的 `.css`，并向页面
  注入 stylesheet link。库构建有独立分支。
- `packages/tsone/lib/core/document.ts` 将 `document.styles: StyleSheet`
  序列化为 HTML 内联样式；同一入口可以按页面路由生成不同内容。
- `StyleManager` 每实例维护规则 Map 和样式节点，支持 `addStyle`、
  `removeStyle`、`clearStyles`、`destroy`。组件卸载会销毁自己的管理器。
- 默认应用文档只包含挂载容器。构建时抓取 DOM 样式无法完整覆盖根组件、
  延迟组件或交互后才创建的组件。
- One UI 常见写法是模块常量数组加 `forEach` 注册；playground 还包含
  直接字面量注册和局部数组注册。发布依赖中的 JavaScript 同样需要分析。

## 方案选择

| 方案 | 影响 | 决定 |
| --- | --- | --- |
| 自动分析现有固定初始化 | 保持应用写法，需要保守求值和运行时回退 | 采用，用户已选择 |
| 新增应用必须使用的静态声明 API | 判定明确，但需要迁移现有组件和样式集 | 不采用 |
| 执行组件后收集 DOM 样式 | 只能覆盖实际实例化的组件，无法证明规则固定 | 不采用 |

CLI 内部使用 TypeScript AST 分析源码和 JavaScript，复用现有
`typescript` 依赖。Bun 构建的内部 transform 负责改写输出，不向
`tsone.config.ts` 增加公开 plugins 配置，不改用户源文件。

## 自动分析范围

分析只作用于 Bun 实际解析到的模块。模块解析与 Bun 的入口、导出条件、
项目路径配置一致，不能将用于类型解析的 `.d.ts` 当作运行代码。
类继承和 `StyleManager` 构造器身份通过导入绑定、别名和继承关系确认，
不能仅匹配类名或 `addStyle` 方法名。

每个唯一入口先执行一次 `write: false` 的 Bun 发现构建，内部插件记录
`onLoad` 提供的实际规范路径和源代码。发现完成后建立绑定图，再执行已有
站点写盘构建并变换确认的源码组；不能在图还未完整时猜测依赖身份。两次
构建使用相同入口、browser target 和解析配置，发现构建不生成发布文件。
首次构建成本会增加，本优化针对站点产物和运行时样式承载，不承诺缩短
构建时间。分析器只在
相对引用、项目路径映射或包导出能唯一对应已加载模块时建立绑定边，并读取
对应包 manifest 确认 TSone 身份。重导出沿已确认的边追踪。存在 browser
条件分叉、插件改写、无法证实的路径映射或两份依赖导致身份歧义时，跳过
相关注册组；不把独立 TypeScript 或默认 Bun resolver 的猜测当作 browser
解析结果。首版不承诺对所有条件导出都提取。

首批支持以下注册形态：

- `initStyles()` 中连续的 `this.styleManager.addStyle(name, options)`。
- 局部固定数组的 `forEach(style => ...)`。
- 模块固定数组的 `forEach(({ name, ...style }) => ...)`，覆盖 One UI
  常用形式。
- 从 TSone 导入的 `StyleManager` 新建实例、未发生别名逃逸或其他操作前的
  连续固定注册。已存在的管理器或身份不明的对象保持原调用。

常量求值支持字符串、数字、负数字、对象与数组字面量、括号、类型断言、
`satisfies`、可解析的常量绑定、对象属性、纯对象展开和模板插值。压缩
JavaScript 中的 `var`、`let` 仅在绑定分析确认初始化后没有重新赋值时
作为候选处理，同时追踪类名和导出别名，不能依赖源变量名或 `const` 关键字。
`Object.freeze` 仅在绑定确认为标准内建时处理。纯函数仅支持参数及默认值
加一个返回表达式的有限子集，例如 `oneThemeBorder` 的模板字符串；解析
表达式求值，不执行应用函数，不使用 `eval` 或导入应用代码作为分析器。

读取 props、state、时间或环境，未知函数、getter、复杂控制流、无法解析的
继承、循环模块依赖、未知计算属性、管理器别名、可见数据修改，均使对应
注册组保持原代码。声明为 `const` 不等于对象不可变。

每个组必须完整得到有序的命名规则。注册组边界不能跨越可观察的管理器操作
或其他副作用。额外调用保持原位置，例如 `OneLoading` 的 keyframes 初始化；
无法隔离时整个初始化保持原路径。

解析不到源码或遇到不支持的语法，只跳过该组。分析器的内部错误、生成无效
代码、CSS 写盘失败属于构建错误，不能静默伪装为成功。

## 模块职责和关系

- CLI 分析器识别绑定、注册组和可求值数据，输出有序规则及源码变换信息。
- CLI 样式产物模块负责确定文件名、登记输出、页面目录分发和文档样式替换。
- CLI 构建模块组合分析器、样式产物模块和现有 Bun 构建。
- 框架提供无 DOM 依赖的管理器规则序列化函数，供运行时与 CLI 使用同一套
  转换，保持现有 `StyleManager` 的基础、hover、media 和属性转换行为。
- `StyleManager` 组合自己的内联节点、候选外链节点及加载状态，负责实例
  生命周期。共享加载缓存只保存 CSS 文本获取结果，不共享激活节点。

这些关系是模块依赖及管理器对 DOM 节点的组合，不引入新的继承体系。
分析器不负责写文件，产物模块不判断响应式状态，框架不依赖 CLI 或 TypeScript。

## 组件静态样式运行协议

增加供生成代码使用的 `StyleManager.useStaticStyleSheet(href)`。生成代码
完整保留原注册代码，包括逐项求值、`forEach`、`addStyle` 调用、对象引用
及其他副作用的原顺序，只在完成候选组注册后附加静态外链申请。旧框架
没有该方法时，跳过附加申请，原代码继续运行。

首版不将注册替换成批量 Map 写入，也不重新执行初始化。这样不绕过
`addStyle` 覆写，不改变消费者加入 getter、Proxy 或自定义 `forEach` 后
的同步观察顺序。管理器被覆写、节点被直接操纵、现有样式不完整或不能
取得可信的内联快照时，不申请外链。

加载流程如下：

1. 原初始化已同步生成内联样式，保持挂载和尺寸测量时的样式可用。保存
   实际写入节点的 CSS 原文、节点身份和加载代次作为快照。
2. 获取对应 CSS 文本，按绝对 URL 在运行时缓存共享的获取 Promise。
3. 将 CSS 文本与步骤 1 的快照逐字比较，不能在 await 后重新读取可变规则
   对象来判断是否匹配。保持管理器 CSS 产物原文，不对它另外压缩。这一步
   处理导出数组被消费者修改等运行时差异；不使用可能碰撞的短 hash 代替
   内容比较。
4. 内容相同且管理器未变化、未销毁时，在原样式位置创建该实例自己的候选
   stylesheet link。候选使用 `media="not all"`，在设置 href 或插入节点前
   安装 load/error 回调；不依赖 disabled 状态必然触发加载。加载期间
   保持内联有效、候选 link 不参与层叠。
5. link 加载成功且代次、原节点身份及其 CSS 原文仍与快照相同时，启用
   link 并移除内联节点。网络、CORS、加载失败或内容不同，继续内联路径，
   不阻止应用挂载。再次申请、修改、清理和销毁都使旧代次失效。

不同实例可以引用同一文件，浏览器缓存复用资源，但每实例保留独立的激活
节点和插入位置。不能按全局规则名称或 selector 只保留一个常驻 link。

`addStyle`、`removeStyle`、`clearStyles` 使加载状态失效。已经静态激活的
管理器从完整 Map 生成动态样式，在原节点位置替换 link；不能追加到 head
末尾改变优先级。之后继续现有动态路径。`destroy` 清理本实例所有节点，
使晚到的获取和 load 回调失效；共享资源请求不因一个实例销毁而取消。

`styles` 仍保存完整有序 Map。`styleElement` 保持 `HTMLStyleElement | null`
类型；内联阶段指向实际节点，外链激活后为 null。静态模式的外链是私有实现。
保证 `StyleManager` 方法的行为；直接操纵公开节点的应用代码不纳入静态快路，
可观察到这类使用时保留原初始化，并在文档说明静态模式的节点内省差异。

## 文档固定样式

框架生成 `document.styles` 的 style 节点时添加内部标记
`data-tsone-document-style`。CLI 使用 Bun 原生 `HTMLRewriter` 只处理带该
标记的 head style，在原位置换成 link。用户手写的 head/body style、脚本
字符串和元素内联属性不参与抽取。

每路由使用最终渲染结果，不能按 entry 直接缓存文档 CSS。空样式集不生成
空文件。同一目录内相同内容复用内容 hash 文件名，不同内容互不覆盖。

Bun 导入 CSS、head 参数和脚本注入沿用现有构建流程，固定文档样式的 link
保持原来 style 所在位置，不修改 `OneApp` 的通用 head 覆盖语义。现有 build
传入 head 会覆盖应用 document.head，这个独立问题不纳入本次修复。
自定义 renderer 忽略 options 或没有 head 时，保留其实际返回结构，不补造
文档；仅在存在受控 head style 时抽取。

## 输出路径与资源地址

CSS 使用保留前缀加完整 SHA-256 内容摘要命名，避免与 Bun 的 `main.css`
等产物冲突。组件产物不作为全页永久生效的 stylesheet 注入，只由管理器
激活。文件全部计入 `BuildResult.assetsBuilt`，返回路径去重。

组件 CSS 由独立产物模块写盘和登记，不进入 `buildPage` 对 Bun 输出的通用
`stylesheetAssets` 列表。文档 CSS 通过原节点替换引用。两类文件和 Bun 导入
CSS 明确分角色，避免组件固定规则被提前永久激活。

生成 CSS 放在对应 HTML 同目录；组件 CSS 按使用该入口的页面目录分发。
运行时引用该目录内的文件，兼容同入口多路由、嵌套 `.html` 页面和
`directoryPages`。`basePath` 是部署 URL 前缀，不生成额外的磁盘目录。

首版对地址语义使用保守回退：规则包含相对 `url(...)`、片段 URL、
`@import` 或无法确定的 CSS URL 时，整组保留内联或运行时处理。绝对 URL、
根相对 URL 和 data URL 可保留。存在 HTML base 元素时，文档抽取及组件
静态激活保留原路径。这样避免外链 CSS 改变相对资源、SVG 片段或历史路由
变化时的解析基准；本次不新增资源复制或 CSS URL 重写子系统。

重建继续使用现有安全目录检查和清理流程。没有固定样式时，产物维持现状。
`tsone dev`、watch 和 `tsone build --library` 不启用本优化。

## 验收与验证

行为测试先定义失败，再实现。必要覆盖如下：

- 文档样式输出真实 CSS，原位置引用、规则内容正确、没有固定样式不产空文件。
- 直接字面量、局部数组、模块常量、解构和纯模板函数均能提取；TS 与已发布
  JavaScript 输入都覆盖，包括真实 Bun 压缩后的 One UI 风格 fixture；
  匿名同名对象不被误识别。路径映射、barrel、条件分叉和两份框架依赖
  分别验证可靠提取或完整回退。
- props/state、条件、未知调用、mutation、getter、无法解析继承和管理器别名
  保留原调用；导出常量运行时变化使候选 CSS 回退。
- 导出数组的 getter 读取前项 Map/节点、自定义 forEach 和 addStyle 覆写
  仍按原顺序执行；等待加载期间仅修改规则对象不能使新样式意外生效。
- 多个实例同 selector 的顺序正确；add、覆盖、remove、clear、destroy、
  动态修改后删除均保持 Map 与实际样式一致。
- CSS 获取或 link 失败时仍有同步样式；加载途中修改或卸载不产生晚到节点；
  样式完成加载后移除重复内联节点，保留原位置。
- 多页面、共享入口、嵌套路径、目录页面、basePath、导入 CSS 与脚本沿用
  原注入行为；自定义 renderer 结构保留。CSS URL 与 base 元素按边界回退，
  不重新定义已有 Bun 资产对 base 的解析语义，产物不撞名且重建无旧文件。
- dev、watch、library 保持原流程；真实 CLI 安装消费者的 build/dev、类型和
  动态回退可运行，不依赖仓库源码路径。

先跑分析器、样式管理器、build/project/multipage 最小测试，再扩大到 CLI
全量、框架组件与文档契约、类型检查、lint 和仓库构建。发布面检查包含两个
包的 package smoke 或 dry-run pack。浏览器验证重点是样式测量、外链加载、
多实例层叠与卸载，DOM mock 的通过不能替代这些检查。验证失败区分新引入
问题与已复现的原有失败，不通过修改无关文件掩盖。
